# Limitations and Future Work

## Limitations

The project should be presented as an academic prototype rather than a completed municipal waste-management platform.

Key limits documented or implied by the implementation scope include:

- Prototype-scale single-bin monitoring.
- Dependence on Wi-Fi connectivity.
- Rain handling is based on binary detection rather than a richer environmental model.
- The accessible publication does not provide the complete original pin mapping/source repository.
- The cloud interface is based on ThingSpeak rather than a bespoke production backend.
- Reported performance values are based on the authors' test setup and should not be treated as a general city-wide benchmark.

## Future work documented in the publication

### AI-based waste classification

Machine learning could be added to identify waste types and support more advanced waste handling.

### Mobile application

A dedicated mobile application could make status and notifications more accessible to end users.

### Solar / renewable power

A renewable power option is identified as a route for improving long-term field deployment.

### Advanced routing and operational analytics

The project can be extended beyond sensing to more advanced collection planning and route optimization.

## Potential cybersecurity extension for a future version

A future engineering iteration could also document device identity, credential protection, encrypted transport, firmware update security, and cloud access control. Those items are not claimed as implemented by the original project unless supported by the recovered source.
